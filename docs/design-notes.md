# Design Notes

Meden Lens starts with a simple product belief: AI agent usage should be evaluated relative to the task, not only as raw telemetry.

A run that spends many tokens, tool calls, or dollars is not automatically bad. It may be justified for deep research. The same usage can be excessive for a simple transformation or document summary. The MVP is designed around that distinction.

## Decisions

### Deterministic Scoring First

The MVP uses deterministic scoring instead of machine-learned judgment.

This keeps early results explainable and testable. Every analysis can be traced back to the declared task profile, the actual run metrics, the configured scoring weights, and the findings generated by the rules.

### Task Profiles As Explicit Policy

Task profiles are the first version of the product's ground truth.

They define expected budgets for each task type: model calls, tool calls, tokens, duration, cost, retries, and sub-agent usage. This makes the product useful before historical data exists.

### Static Profiles Before Adaptive Baselines

The first task profiles are static seed data.

That is intentional. Static profiles are easy to reason about, easy to test, and easy to discuss with a team. Later versions can add input-size-aware budgets and historical percentile baselines without removing the explicit policy layer.

### Analysis Before Runtime Blocking

The MVP analyzes completed runs instead of blocking agents at runtime.

This reduces product risk. Teams can inspect findings, compare them with real expectations, and tune the scoring model before turning any insight into an automated guardrail.

### Explainability Over Hidden Optimization

The first version does not try to silently optimize agent behavior.

It returns a balance score, a classification, supporting metric scores, findings, recommendations, and estimated savings. The goal is to make the decision understandable enough that a developer or manager can decide what to change next.

### Backend Core Before Dashboard

The project starts with the backend API, persistence model, and scoring engine.

A dashboard will be more useful once the underlying domain model is stable. This also keeps early commits focused on product logic rather than presentation.

## What This Means For Users

In the current MVP, a user can submit an AI agent execution run and ask Meden Lens:

```text
Was this level of resource usage proportional to the task?
```

The answer is not only a score. It is an explainable decision with the evidence behind it.
